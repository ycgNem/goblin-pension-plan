# Goblin Pension Plan — project notes

A top-down action RPG in strict TypeScript, Vite, and raw Canvas 2D. Read `docs/DESIGN.md` for the game and `docs/MILESTONES.md` for where the build is.

## Commands
- `npm run dev`: dev server on port 5180 (also `.claude/launch.json` → "dev")
- `npm test`: Vitest. Run it after any change to `src/data/`, `src/world/maps/`, or creature, human, event, or inventory logic.
- `npm run typecheck`: must stay clean. `strict` and `noUncheckedIndexedAccess` are on.
- Pushing to `main` deploys: `.github/workflows/deploy.yml` runs the tests and the build, then publishes `dist/` to https://ycgnem.github.io/goblin-pension-plan/. Vite builds with `base: './'`, so keep asset paths relative (no leading `/`).

## Rules
- **TypeScript only.** No `.js` source files. No runtime dependencies without a strong reason (the brief says to avoid them). The two Fontsource fonts are the exception.
- **Content is data.** Items, nodes, recipes, upgrades, creatures, people, events, combat tuning, skills, regions, charter, economy, and story text live in `src/data/*.ts` as `as const satisfies Record<string, Def>`. New content and tuning numbers go there, not in logic code. When you need an optional field off one of those unions, annotate it (`const r: RecipeDef = RECIPES[id]`). Add a test in `tests/data.test.ts` or `tests/content.test.ts` when you add a new kind of cross-reference.
- **Maps are ASCII** in `src/world/maps/`. The legend is in `src/world/tiles.ts`. Exits are digits linked in `src/data/regions.ts`. `tests/world.test.ts` checks two-way links, reachability, gates, and safe regions, and `tests/events.test.ts` checks event routes and zones, so run both after any map edit.
- **Logic stays DOM-free.** `src/game/` (scene, creatures, people, director, inventory, crafting, production) never touches the canvas; drawing lives in `src/render/`, `src/ui/`, and `src/app/`. `game.ts` and `game-hud.ts` are the glue between them. That split is what lets `tests/helpers.ts` build rooms and run scenes in Vitest.
- **The scene is runtime-only.** `src/game/scene.ts` holds a region's creatures, people, objects, pickups, and effects, and is rebuilt on every region entry. Save data (`src/game/save.ts`) is only what persists. Floor pickups are the one carry-over: `save.floor` keeps them per region until the Shift Bell. `parseSave` fills in missing fields from `newSave()`; bump `SAVE_VERSION` and write a `migrate` step only when the shape changes incompatibly.
- **Two drawing layers.** Pixel art (terrain, sprites, panels, icons) goes on the low-res game canvas; text goes on the full-resolution UI canvas through `Hud.text`. A `Hud.panel` wipes the text under it, so windows stack correctly.
- **The view size changes.** `VIEW_W`/`VIEW_H` in `src/core/screen.ts` are live bindings (480–640 by 270–360) that follow the window's shape, so never cache them at module load. Lay out HUD pieces from the view edges, and center fixed-size windows and screens on the 480×270 stage (`BASE_W`, `BASE_H`, `stageOrigin()`, `hud.origin()`).
- **Keys are actions.** Gameplay reads `input.hit('roll')` / `input.held('sneak')` and shows keys with `actionLabel('throw')`, never a hard-coded key code, because players can rebind them (`src/core/keys.ts`).
- **Art is being overhauled** to PixelLab-generated pixel art (`docs/ART_PLAN.md`: plan, style guide, budget, and the generation ledger; update the ledger with every generation). Generated art is packed PNGs in `src/assets/art/`, loaded at boot by `loadArt()`, and drawn through `SheetSprite` (`src/render/sheet.ts`, same contract as `Sprite`), the dual-grid terrain (`src/render/terrain.ts`, sets per region in `src/render/art/regions.ts`), `propArt` (props.png: every prop state; signs and plaques get their lettering from the prop's `label` inside its `board`), `portrait` (portraits.png, with talking and blinking drawn over each bust), `drawIcon` (icons.png: every item and decoration at 16px; every row, chip, and slot that shows an icon gives it a 16x16 box), and the title and intro paintings (`src/app/backdrops.ts`: the animation layer draws at each painting's `marks`, and painted panels hold still because zooming smears pixel art). Everything not yet replaced is still code: string sprites (`characters.ts`, the HUD glyphs in `icons.ts`, checked by `validateSprite`), the hearts, and terrain overlays (pipes, gates, exits). Keep the code art as the fallback when an image isn't loaded (and in tests). Effects, telegraphs, cones, and awareness icons stay code.
- **Art pipeline:** raw downloads go in `art/raw/` (committed), `art/sheets.json` says how to pack them, and `npm run art:pack` writes the PNGs and `src/render/art/sheets.gen.ts` (never edit that by hand). `node scripts/art/fetch.ts <dir> name=url…` downloads; `node scripts/art/contact.ts <out.png> <scale> <files…>` makes a zoomed review sheet. `node scripts/art/pull.ts <id> <name> [characters|objects]` unpacks a PixelLab character or object. `tests/art.test.ts` checks sizes, clips, prop and portrait boxes, icons, backdrop marks, and that every map's terrain resolves to a real tile.
- **Units:** world pixels; one tile is 16px. Damage to the goblin is in half-hearts. Time is in seconds. Production, shifts, and events run off `save.playTime`, never wall-clock time (no offline decay).
- **Design guardrails** (from the brief): the Burrow is always safe; no hunger, durability, raids, or permadeath; pursuit always ends; creatures only hurt with telegraphed attacks; people never take loot or use crawlspaces; quest items never come from random drops; basic crafting never needs power; decorations never cost copper or quest items.
- **Voice:** one-line jokes, at most 80 characters for item descriptions and 50 for speech bubbles. See `docs/CONTENT.md`.

## Workflow
- Work milestone by milestone. Tick boxes in `docs/MILESTONES.md` as things land, and keep each milestone playable.
- Verify in the browser before calling a gameplay change done. Unit tests don't cover feel.
- Dev builds expose the app as `window.__app` and the running game (or `null` on the title screen) as `window.__gpp`. If the Browser pane is hidden, the page gets no animation frames and everything freezes; step it by hand with `__app.update(1 / 60); __app.input.endTick();` and call `__app.render(60)` before reading the canvases. Dispatch `KeyboardEvent`s on `window` to press keys.
- To see a frame while the pane is hidden, draw the `#game` and `#ui` canvases onto one canvas and export it (for example, POST it to a small local receiver in the scratchpad and read the PNG). `#game` is the scaled display canvas; the low-res frame itself is `__app.screen.lowres`. Teleport with `__gpp.player.x/y` (the scene's goblin copies it every update).
- Tune combat and stealth with bot runs from the console and compare outcomes across play styles, as recorded in the M1 play-test notes.
